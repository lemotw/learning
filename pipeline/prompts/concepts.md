# 概念萃取規格(meta.json 的 concepts 欄位)

concepts 是課程關聯計算的資料來源(路線:概念 embed + MaxSim 比對,見 GraphRAG 模式)。
**萃取發生在課程生成/內容大改的 session 裡**,不在關聯腳本執行期——腳本只讀 meta.json,零 LLM 依賴。

## 格式

```json
"concepts": [
  { "name": "B+tree 索引", "desc": "高扇出多層樹狀索引結構,千萬列資料樹高僅三四層,以 page 為最小讀取單位" }
]
```

## 萃取規則

1. **數量 8-12 個**,來源是 AGENDA(課綱)全文。
2. **name:裸名詞片語(2-10 字),領域具體**——「B+tree 索引」「gap lock」「頭肩頂型態」,不是「索引優化技巧」這種模糊詞。
3. **禁模板/教學詞**:單元、Lab、自答題、診斷、實作、驗收、整合、檢查表、學習、課程、專案——這些是文體,不是知識指涉物,混入會汙染關聯比對。
4. **desc:一句話(15-30 字)直白定義**,寫給機器做語意比對用,不用文采。
5. 概念間不重疊;優先選「能代表這門課、且可能與其他領域呼應」的概念(例:db_scale 選「quorum 共識」就有機會對上 k8s 的 etcd)。

## 維護時機

- `/new-course` 階段 4(課綱固化)時萃取並寫入 meta.json。
- 講義/課綱大幅改動時,由改動的那個 session 順手重萃取。
- 存量補跑/手動補救:`claude -p` 或 Ollama 本機模型皆可,規則同上。
